# ラスト・エレベーター

約3分のターン制ルート戦略ゲームです。`/?game=last-elevator` または一覧の新作バナーで開きます。標準モードは電力52・18手・定員5人。練習モードは電力72・24手・定員6人で、住民の待機時間も5手長くなります。時計のカウントダウンはありません。

## 遊び方と作戦

階を選び、「向かう」で移動します。呼び出しのある階では、助けになる住民を優先し、ほかは期限が近い順に定員まで乗せます。1Fの避難所へ届けると救出完了。途中で別の階に寄ることもできます。住民は期限を過ぎると階段チームへ移り、その便での救出対象から外れます。

通常走行は1手、節電走行は2手を使います。帰還用の電力と時間は必ず確保するため、搭乗者を乗せたまま動けなくなるルートは選べません。降下は上昇より消費電力が少なく、4手ごとの予告で次の移動コストが変わることがあります。帰還の予約電力には次の予告分も含めます。

- 電気技師を届けると、予備電源で電力＋8
- 防災リーダーを届けると、定員＋1
- おばあちゃんと孫を届けると、待機中の全員に猶予＋2手

助けた住民の効果は一度だけ発生します。先に誰を届けるかで、その後に選べるルートが変わります。

救出1人につき100pt、期限の2手以内で搭乗させると1人35ptを追加。満員の便は100pt、3階以上から乗せた便には80ptの追加ボーナス。最後に残電力×3ptを加えます。14人救出でランクA、18人でSです。診断は満員の便・高層階・期限ぎりぎりの救出の実績を使った娯楽です。

## 相談と目標（改善版）

新しく始めると、能力を持つ3組の救出・高層階8人救出・満員2便の3つから目標を選びます。達成でそれぞれ350・300・250ptを追加します。

最初の帰還後には、上層階の写真部2人からSOSが届きます。引き受ければ6手の期限つき呼び出しが追加され、届けると220pt。別チームに託せば1手かけて電力を8補給できます。2回目の帰還後は照明について相談が届き、電力を増やす代わりに猶予を減らすか、電力を使って猶予を延ばすか、現状を維持するかを選びます。電気技師を先に救出すると、電力の増加量が6から10になります。相談は避難所で、残り3手以上かつ待機住民がいる場合に限り発生します。

救出した住民に応じて、避難所での短い後日談が変わります。相談・目標・分岐は `adventure.ts` で扱い、従来のルート計算は `engine.ts` を利用します。

## データと再現性

`src/rescue/config.ts` に初期資源、住民テンプレート、期限、能力、予告イベントを配置。`engine.ts` はDOMやReactに依存せず、渡された状態を変更しません。

日本時間の日付をシードにした「今日のタワー」は、同日なら同じ配置です。練習モードと標準モードでは資源と待機時間が異なります。結果画面では別の乱数配置も選べます。

保存キーは `small-worlds:last-elevator:v1`。新規ゲームは形式v2でシード・モード・目標・移動と返答の履歴を保存し、読み込み時に進行を再実行します。従来の形式v1は従来のルールのまま再開し、途中に新イベントを差し込みません。不正・破損データを削除せず、新規開始による上書き時に確認します。設定や進行ルールの変更はセーブの互換性を確認し、必要なら形式バージョンを上げてください。

## 検証

単体テストはルート、費用、住民の能力、期限、保存、診断、相談の効果、目標と追加救出の得点を検証します。改善版も60シード×2モードで分岐を変えながら完走し、全手順のセーブ再実行を検証します。100シード×2モードで工夫する戦略と単純往復を比較し、さらにランダムな合法ルートで帰還不能が起きないことを検証します。これは全ルートの最適性を証明するものではありません。

Playwrightはモバイル・PCで開始、救出、住民の能力、保存再開、完走、診断共有、保存失敗に加え、新規相談への返答・移動の待機・返答後の保存再開を検証します。ブラウザの実行環境がファイルURLを制限する場合は、単一HTMLもHTTP経由で依存ファイルのない状態を確認します。実機Safariは別途確認が必要です。

```sh
npm run check
npm run build:demo
```

単一HTML版は `build/last-elevator.html`。公開サイトへのデプロイは実行しません。現実の災害対策やエレベーター利用の案内ではなく、架空のパズルとして設計しています。
