# Cloudflare Pages 公開手順

この構成はPages向けの静的サイトです。この作業では本番公開を実行していません。

## 公開の準備

1. `npm ci` と `npm run check` を実行
2. `npm run preview` で新作2つと `/legacy/` を確認
3. 配信対象が `build/` であることを確認。ソース一式やZIP・セーブデータは公開しない
4. 人間に変更内容・テスト結果・公開先・影響を提示し、**本番公開の明示的な承認を得る**
5. Cloudflare Pages の **Direct Upload** プロジェクトを作成し、実際のプロジェクト名に `wrangler.jsonc` の `name` を合わせる

Git連携による自動本番公開は、この承認手順を飛ばさないよう無効にしてください。通常のGitHub Actions（ci.yml）は検証と成果物保存までです。別途GitHub Pages用の手動公開ワークフローもありますが、Pushでは実行されません。Cloudflareの認証情報はGitやチャットに保存せず、Cloudflareのログインや適切に制限したCIシークレットを利用します。

## 承認後の公開

Cloudflare Pages に **`build/` の中身**をアップロードできます。CLIのコマンド例は次のとおりです。Cloudflareのアカウント・プロジェクト・認証が必要です。まだ実行していません。

```sh
npx wrangler login
npx wrangler pages deploy build --project-name <実際のプロジェクト名> --branch main
```

Wranglerはアプリの実行・ビルドには不要な公開用ツールです。バージョンは実行時にCloudflareの現行推奨版を確認してください。CLI認証が使えなければ、承認を得たうえでDirect Upload画面を使います。

| 項目             | 値                                             |
| ---------------- | ---------------------------------------------- |
| Node.js          | 24                                             |
| ビルドコマンド   | `npm run build`                                |
| 出力ディレクトリ | `build`                                        |
| ゲーム一覧       | `/`                                            |
| ゲーム選択URL    | `/?game=tower-lab` または `/?game=island-town` |
| 原作版           | `/legacy/`                                     |
| シークレット     | 静的ゲーム自体には不要                         |

ルートパスでの配信を前提とします。サブディレクトリへの配信にはViteのbaseと原作リンクの調整が必要です。`public/404.html` は存在しないパスへの案内。`public/_headers` は公開時のCSP・権限制限・キャッシュ方針です。Vite previewはPagesのヘッダー処理を再現しないため、公開先でも確認してください。

## 公開後の確認と戻し方

承認された公開の完了後、新作の開始・保存再開・結果共有、原作版、モバイル表示、404、レスポンスヘッダーを確認します。セーブはオリジン単位なので、ドメインを変えると以前のドメインの保存データは見えません。旧公開サイトは別途明示されない限り変更しません。

問題があればCloudflare Pagesで直前の正常なデプロイへロールバックします。新バージョンのセーブを旧版で無理に再生することはできません。公開前に互換性の扱いを決めてください。

これらの設定ファイルは公開準備であり、Cloudflareでのデプロイ・公開確認が成功したことを意味しません。
