# 零時の残響

貞子をモチーフにした、オリジナルの非公式短編ホラー脱出ゲームです。長い黒髪・白い服の影、井戸、呪いの映像を使い、部屋の探索と封印の暗号を組み合わせています。公式素材・映像・音源は使わず、背景と人物はCSS・SVGで描画します。

`/?game=zero-echo` または一覧バナーから開始。短編は18手・気配14・電池3、じっくりは24手・気配16・電池4。約3〜5分を想定し、現実の時間は進行に影響しません。音声なしで遊べます。

## ルールと解法

居間の映像を調べると、三つの部屋の順番が分かります。浴室・書斎・井戸にある記号を集め、玄関で映像の部屋順に記号を並べて封印します。書斎で得た鍵が井戸への入口を開きます。各部屋の記号と部屋順は独立してシードから抽選し、メモに自動記録します。

行動は各1手。テレビが点灯していると毎回気配＋1ですが、次の危険を予告してくれます。足音のときに移動するとさらに＋3、視線のときにライトなしで調べるとさらに＋3です。ライトは電池1で視線の追加分を防ぎます。浴室で得た護符は後の視線を一度防ぎます。

プラグを抜くと次の行動から基本の気配増加が止まり、予告も見えなくなります。テレビを消す前に映像を確認し忘れても、居間で電源を戻せます。息をひそめると気配−2（テレビの＋1とは合算）ですが、連続使用は逆に＋2。すでに調べた場所の再調査も＋2で、手がかりは増えません。

印を並べる操作だけでは手数を使いません。封印を実行すると1手。誤った封印は気配＋4、正しい封印は最後の手でも脱出が優先されます。気配か猶予が限界に達すると夜に取り込まれます。生還時の診断はテレビの使用と休息の傾向で変化します。

## 構成と保存

`src/haunt/config.ts` に部屋・アイテムの説明、モード資源、予告と基本ルールを配置。`engine.ts` はDOMに依存せず、渡された状態を変更しません。`HauntGame.tsx` と `haunt.css` が表示と入力を担当します。

保存キーは `small-worlds:zero-echo:v1`。シード・モード・操作履歴を保存し、Zod検証後に再実行して状態を復元します。最大24手・サイズ上限つきで、未到達の井戸や不正な操作を拒否します。壊れた保存は自動削除せず、新規開始の上書き時に確認。保存を拒否された場合も通知して遊べます。ほかのゲームの保存には触れません。

外部通信・音声・実行中の時計・個人情報入力は不要です。共有ボタンを押したときだけ、結果文を端末の共有機能またはクリップボードへ渡します。共有文に暗号の解答や保存履歴は含めません。

## 検証と配布

`npm run check` で全ゲームの検証を実行します。単体テストでは100シード×2モードに脱出可能なルートがあることを確認し、手がかり・鍵・護符・予告・電源の復旧・誤答・両方の失敗条件・保存再実行を検証します。全ルートの最適性を証明するものではありません。

Playwrightはスマホ・PCで最初から実操作して暗号を解く完走、結末の共有、保存再開、電源復旧、失敗結末、上書きのキャンセル、保存失敗を確認します。実機Safariは未検証です。

`npm run build:demo` で単一HTMLの `build/zero-echo.html` を生成。端末によってローカルHTMLの実行・保存に制限があるため、スマホでは承認後に公開URLで提供する想定です。公開ブランチの `zero-echo.html` に追加すれば既存ゲームのURLを維持できます。制作・テストだけでは本番公開せず、人間の承認を得てから行います。
