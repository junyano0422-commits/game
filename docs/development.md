# 開発ガイド

## 設計

```text
ゲームJSON → 設定検証 → 共通エンジン → React画面
                            ↓            ↓
                         選択履歴 ← 保存・再開
                            ↓
                       診断・共有テキスト
```

`core` はDOM・React・localStorageを参照しません。状態を引数で受け取り、変更後の新しい状態を返します。UIは結果を表示します。保存だけがStorage相当のインターフェースを受け取ります。

`decision → report → 次のdecision / finished` の順に進みます。レポートを挟むことで、結果を読む前に年が進むことを防ぎます。各選択で次の順に処理します。

1. 選択肢と支払い可能な状態を検証
2. 同じ方針の連続によるプラス効果の低減（支出は減らさない）
3. 選択による直接の効果と通常の年間運営
4. 過去に予約した効果を1回だけ適用
5. 選択とは独立した相場と、連続方針による満足への負担
6. 設定された上下限への丸め、終了条件の判定、履歴記録

未来イベントは `requires` / `excludes` のフラグ、`minTurn`、メトリクスの `when` 条件で制御します。`priority` のイベントを先に選び、それ以外は重み付き抽選。直前と同じイベントは避けます。設定検証で無条件のフォールバックを2つ以上必須にし、進行不能を防ぎます。

## ゲームを追加する

1. `src/games/island.json` をコピーし、一意な `id` と `version` を設定
2. メトリクスの名称・単位・初期値・上下限、モード、経済、イベント、診断を編集
3. `src/games/index.ts` にJSONのimportと `parseDefinition` による登録を追加
4. `npm run check` を実行し、Playwrightに新しいゲームの完走も追加

JSONの構造は `schema.ts` が唯一の定義です。各イベント・選択肢の `id` は表示文言から独立した変更しない識別子にします。各イベントにはすべてのメトリクスの支出がないフォールバック選択肢を少なくとも1つ置きます。

資金・資産・人口・満足・備えの5メトリクスは共通です。別の種類が必要なら、JSONだけで無理に代用せず、スキーマ・エンジン・表示を一緒に拡張してテストを追加します。設定はスキーマに通るだけでなく、複数シードで実際に完走させてください。

## バランス調整

`engine.test.ts` は2ゲーム×50シード×2モード×4方針の800プレイを実行します。数値の上下限、途中終了、完走条件を確認し、現在の設定では混合戦略の平均評価が各単一戦略を上回ることを検証します。すべての選択列の最適性を証明するものではありません。

イベント追加時は発生条件・支払い可能な代替案・連続方針の負担・投資回収までの年数を確認します。最終年までに回収しない投資は結果画面に未回収件数として表示し、未発生の効果をスコアに足しません。約5分という読了時間は設計上の目安であり、プレイテストで確認してください。

## 保存の互換性

キーは `small-worlds:v1:<game-id>`。形式バージョン・ゲーム設定バージョン・シード・モード・選択履歴・フェーズだけを保存し、復元時にエンジンで再実行します。計算済み資産を入力として信用しません。

**既存イベント、選択肢、効果、抽選、進行ルールを変更する場合は `version` を上げてください。** 現在は異なるバージョンの再生を拒否し、元データを保持したまま知らせます。データ移行機能はまだありません。継続可能な本番セーブがある場合は、過去の定義・エンジンを保持するか、移行処理とテストを先に用意してください。

ブラウザ保存は端末間同期されません。保存できない場合はその条件を知らせます。破損セーブを勝手に削除しません。新規プレイによる上書きは確認ダイアログを出します。

## 既存ゲームの保守

原作のアプリ7ファイルは `public/legacy/` に保持します。既存テストは参照先のパスを更新し、元のロジックとアサーションを維持しました。加えて、原作の共有リンクと結果画像が移動先 `/legacy/` を指すようURL生成を修正し、共有URLの検証を追加しました。`public/legacy/package.json` はNodeの既存CommonJSテストのために追加したもので、ブラウザ実行には影響しません。

原作の10年・30年モード、7物件、会計、診断、共有は既存エンジンのまま動きます。新しいReact版は同じゲームの完全移植ではありません。移行は機能ごとに互換性を確認して進めてください。

## 作業の確認

```sh
npm run format
npm run format:check
npm run check
```

整形対象から原作ファイルを除外しています。Playwrightはビルド成果物を検証するので、変更後は `npm run build` が必要です。失敗時のスクリーンショット・traceは `test-results/`、CIのHTMLレポートは `playwright-report/`。CIに個人のセーブやシークレットは不要です。
